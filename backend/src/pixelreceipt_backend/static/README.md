# 收據 Dashboard（網頁介面）

無 CDN、無前端套件依賴的繁體中文響應式介面。靜態來源由 FastAPI 明確 allowlist 提供；`README.md` 與 `tests/` 不公開。公開路徑可為 `/receipts/`；所有 API 路徑由同目錄的模組 URL 解析，不固定網域。

正式入口先查 `GET /v1/session`，未登入轉到後端 `/auth/login`。密碼與工作階段由後端管理；JavaScript 只在記憶體保存 CSRF 值，修改加上 `X-CSRF-Token`，不保存長期憑證。原圖經同源認證取得後以 blob URL 顯示，用完撤銷；PDF 只提供有頁碼標示的原檔連結，不假裝產生頁面縮圖。

`?demo=1` 是明示的合成示範，不存取正式 API、不執行帳務計算，也不能入帳。正式 API 錯誤不會切換到示範資料。

本文件描述網頁 Dashboard：儲存核對、查看計算結果，再勾選確認並入帳。Android 0.5.0 的原生流程另見 [手機使用說明](../../../../docs/MOBILE_APP.md)；App 以最後一次明確「確認入帳」涵蓋內容與完整性，不另要求網頁勾選。

## 核對邊界

- 金額為 TWD 整數元，空白為 `null`，零元為 `0`；前端不加總、不計算折扣、不乘數量。所有計算結果來自已儲存版本的伺服器回覆。
- API JSON 先檢查數字 token，再 `JSON.parse`；超出安全整數的資料整體停止載入，避免先四捨五入再寫回。
- `buildReview` 省略未知用途與不完整分配。部分填寫的 split 在儲存後保留於本頁並明示尚未送出，不補零；可下載包含本頁未存欄位的核對檔。
- 直接指定金額也需各用途數量。零數量用途不得分配非零金額。實際合計與可入帳條件仍由後端驗證。
- 已含行金額的折扣不提供再次分配。更改品項事實會清除該列用途、加減項分配、完整性與容差接受，要求重新核對。
- 容差接受僅在後端回 `within_tolerance` 時提供，改動內容會清除接受。確認入帳另需明確勾選。
- revision 衝突停止寫入；review 網路結果未知時要求重新讀取，不盲重送。confirm 使用同一 request 與同一冪等 key 重試，不自行換 key。

## 完整期間摘要與商品價格

- `GET /v1/overview` 以起迄收據日期統計所有符合範圍的未作廢帳本，顯示票面付款、用途、個人支出、代墊、獨立差額與收據明列折扣。前端不加總分頁資料。
- 帳本搜尋將店家／品名、日期、狀態交給後端先篩選再分頁。商品目錄也使用完整範圍搜尋，商品建立使用固定內容與同一冪等 key 重試。
- 已入帳明細提供逐列人工商品對應，明確確認同規格及一個購買單位。解除／更換既有對應需要確認影響；完整替換與撤銷保留獨立價格 revision 與歷史，不改原帳務。
- 商品價格分配獨立於用途分配。已含行金額折扣不再分配，單列 scope 由後端直接處理，共用加減項可選固定比例或明確逐列金額；指定方式每個適用列必須填寫，零也需明填。
- 同商品同規格的價格歷史與全範圍最低觀測來自後端；精確價格以 `display_yuan` 顯示，例如 `189 / 2`，不作浮點除法。`printed_unit_price` 標示「行金額換算單價」，不混同原圖印刷單價或原價。
- 來源可回查原帳本、原圖與價格核對歷史。已作廢資料只供回查，不參與摘要或最低價；未購買促銷／報價不納入。
- 登入頁只沿用後端表單與外部 CSS classes，不改認證流程。所有新增 UI 均保持 CSP `script-src/style-src 'self'` 相容。

上述是前端接線與本機函式驗證範圍；實際 HTTP、完整流程與手機視窗由原目標對話統一驗收。

## 驗證

在專案根目錄：

```bash
node --check backend/src/pixelreceipt_backend/static/app.js
node --test backend/src/pixelreceipt_backend/static/tests/*.test.mjs
```

這些測試涵蓋數字精度、未知值、v2 review 分配契約、過期歸屬清除、認證請求、冪等 request、商品身份與價格分配、精確分數與注入邊界。它們不代替實際 HTTP／登入、手機排版、完整流程或人工驗收；整體瀏覽器核對由原目標對話執行。

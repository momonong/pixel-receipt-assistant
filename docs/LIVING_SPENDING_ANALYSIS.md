# 生活支出分析：怎麼記、怎麼看

適用於 0.7.0。正式後端與手機均須支援此版；App 可從設定檢查更新。使用說明與實際部署、手機接受分開核對。

## 拍收據後

沿用「分享照片與說明 → 核對 → 確認入帳」。用途預設自己用，備註中的代買仍先帶入用途核對。

在核對頁或帳目明細開「分析標籤」，可以查看／修改：

- 每個品項的生活分類、細分類、餐別及同餐群組。
- 品牌、分店、店址、縣市、行政區與線上／實體通路。
- 消費時間、日期來源。

部分欄位會由明確補充說明、收據附加資訊或可解釋規則預填；未確定就保留未知。保存標籤有明確結果。分類與地區不完整仍可入帳，之後再補，原有確認金額與原圖不會被改寫。

收據無日期時補入的日子，以及手動改過的日子，會建議為人工確認；只有原始印刷日期未變時才自動標為收據日期。

同張全聯收據可同時有食材與清潔用品。生活分類回答「買什麼」，自己用／送人／代買回答「誰負擔」，兩者分開。

## 沒有收據

從帳本開「手動記帳」，填入整數金額，日期預設今天、用途預設自用。品名／說明、商家及分析標籤都可選填。

核對畫面上的金額與用途後，按「確認記帳」。這會建立正式手動帳目，不需照片，來源會明示手動。房租、水電及訂閱等實際支出可以用這個入口；帳戶間轉帳或尚未消費的儲值不是此入口的支出定義。

一筆手動帳目代表一列負擔。不同用途的支出分開記，不能用說明文字讓模型自行增減金額。

## 看支出

開底部「分析」，先看到期間與個人支出，再看到主分類。個人支出＝自己用＋送人，代買另列；作廢、草稿、菜單及價標不計入。筆數指符合條件的有效帳目，包含純代買帳目；其個人負擔為零，個人餐次則另外排除純代買。

「分析面向」可切換生活分類、細分類、餐別、原始店家、品牌、分店、縣市、地區、消費時間、週間分布、時段、用途或折扣。分類／餐別／店家／地區與日期列可查看支援的對應帳目；週間與時段提供分布檢視。

篩選可以組合，例如「本月＋臺南市＋晚餐＋某品牌」。上方數字與下方帳目使用相同條件，混合收據只計符合條件品項的負擔，不把整張收據都算入一類。切換本月、上月、今年或自訂日期時，比較期間會清楚顯示。開帳目再返回保留分析範圍。

「資料待補」預設收合，點開可看到未分類、縣市／餐別待補、缺日期、採用今天的日期與待分配金額。缺日期帳目保留在全部期間；指定期間不假造日期。舊照片過去未擷取的地區不會憑店名自動猜出。

餐數預設以一筆帳目的一種餐別算一次，多個品項不多算餐。若同一餐分兩張收據，設定同日、同餐別、相同「同餐群組」即可合併計餐。同帳目只需一個一致的同餐代號；若填了不同代號，先保留原本的一餐，請修正一致後再跨帳目合併。全額折扣的個人餐仍算一餐，餐費為零；純代買不降低自己的每餐均額。

收據明列折扣包含符合條件帳目的整張折扣與代買部分，不代表篩選品項自己的優惠，也不代表市場節省。內含行金額的折扣不重扣。額外加減項以整數分配至有依據的品項；無法合法分配的差額明列待分配，分類合計仍與個人支出對得上。

## 比較商品價格

從分析開「商品價格」。先建立或選擇固定品項、品牌、規格及購買單位；不同容量或組合不自動合併。

在來源帳目中逐項選擇商品，人工確認品項及購買單位一致。整張或多品項的額外折扣，可選比例分配，或指定各項金額；內含折扣不再次分配。儲存後查看同商品跨店歷史單價，點來源會回 App 內帳目。

單價使用精確比例。例如兩瓶合計 189 元，以 189／2 表示，不把行合計再乘數量。無法確定實付單價的紀錄仍可查看，但不進最低價排名。「歷史已知實付最低價」只代表已記錄的觀測，不代表現在仍可買到。

## 離線、衝突與重登入

分析無法更新時會標示上次資料；切換條件不能拿其他範圍的舊數字冒充本次結果。分析快取與照片／收據索引分開。同一登入離線重開可讀上次驗證過的報表，舊資料不會授權未經驗證的寫入。

送出後若結果不確定，App 保留同一筆請求，先查詢結果；不會另建新帳目。查詢暫時失敗時保留待查狀態。同一帳本重新登入可接續；不同帳本不會拿到舊帳本的未確定寫入。

若標籤或價格核對出現版本衝突，重新讀取目前內容後再編輯，不直接覆蓋。作廢帳目保留歷史，退出有效支出及商品價格比較。

# PixelReceipt 0.8.0

Android 0.8.0／code 18，名稱仍為 **PixelReceipt**，沿用 `com.momonong.pixelreceipt.mobile` 與永久簽章，可從 App「設定 → 檢查更新」安裝並保留現有資料。

同張照片含多張收據時，中央先定位每張收據，再讀取各自品項。原始整批／逐圖說明會綁定對應區域，讀取後再核對用途；「左邊代買、右邊自己用」不會只留下左邊。群組中每張收據可獨立查看、修正、確認、刪除或作廢，全部入帳才顯示整批完成。無法判定的用途仍交使用者核對，AI 不直接決定正式帳務金額。

設定新增照片空間資訊。已完成且中央原始內容驗證成功的手機副本可回收，需要時再取回；未送出、結果未知或仍有待確認異動的來源照片保留。回收不影響相簿、中央原圖、說明或帳本。離線時仍可看已保存的帳目，未在手機的原圖需要連線取回。

中央原圖採容量與磁碟剩餘空間檢查；可配置 evidence 上限，預設維持 1 GiB，部署時可明確調整。重複照片以內容 hash 共用，辨識 payload 中的圖片改引用已驗證 immutable blob；取用時還原相同 canonical 請求並驗證 hash，未知結果仍沿原 key 查詢。原圖不重編碼、不做垃圾回收，已刪除帳目的歷史證據保留。

備份增加選擇性的 `--previous`：核對前一快照後，僅共用其中不可變照片，資料庫與認證仍獨立複製。各快照可單獨還原，live 原圖沒有 hardlink 到備份。這減少同一磁碟上的重複容量，不能代替異機備份；歷史備份不自動刪除。

Schema 6 只增加多收據工作表。遷移前保存並演練備份，遷移後核對舊表、原圖、帳本識別與認證未改。Schema 5 舊 binary 不可直接回退讀取新資料庫。新 App 的 immutable `receipt_groups_v1` 能力宣告才啟用多收據路徑；未更新 App 的舊收件保持原流程。

既有真實照片測試完整保留左右收據的全部品項，左邊代買、右邊自己用；原圖、票面合計與全部行金額均已對照。辨識輸出與實際金額留在私人測試資料夾；最終用途處理另以這些真實輸出重播驗證，沒有寫入正式帳本。工程驗證、Git 發布、HP 正式部署、APK 下載與手機實際安裝分開記錄，詳見當次交付證據。

本版沒有啟用新供應商、付費備援、商家 embedding 索引或新模型下載。商家相似度建議的資料基礎與後續接入界線見 [多收據設計](MULTI_RECEIPT_AGENT.md)。

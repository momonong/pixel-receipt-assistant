# 收件安全續傳與自動進度

目標：使用者按一次送出後，暫時斷線能沿原請求續傳；收件匣與明細自動顯示中央最新狀態。

沿用 Kotlin/Compose、MobileRepository 的序列鎖與不可變 FrozenIntake。後端已持久輪詢並自動等待 admission，不新增派送端點或其他佇列。

## 行為與界線

- App 前景每 5 秒檢查待處理工作，中央等待資格／容量時每 30 秒更新；返回 App 立即查詢。離開前景停止手機輪詢，中央工作繼續。
- 新送出意圖持久保存安全續傳旗標；暫時網路／408／429／5xx 沿原 key/body/hash 退避 10/30/60 秒續傳。明確拒絕、401/403、本機儲存錯誤或人工停止不自動重送。
- 已取得 intake ID 的任何自動更新只 GET 原工作，包含 unknown；不產生另一個模型請求，不自動入帳。
- 舊版未記錄安全續傳旗標的未確認上傳，保留手動沿原請求重試；一般未送出草稿永不自動送出。
- 每輪最多 8 筆、輪替避免飢餓；目前選取項優先。查詢不佔用全頁 busy、不清除編輯與說明、不搶導航；401 停止並要求登入。
- 明確顯示等待資格、等待額度、離線等待重試及待確認原結果。保留手動更新作備用。
- 免費資格維護仍是獨立營運設定，本次不延長資格、不呼叫供應商、不變更正式服務、不合併推送或發布。

## 選擇

採用現有狀態查詢與前景輪詢，符合不用反覆按按鈕的需求，沒有新依賴。推播／手機常駐背景服務會增加權限與基礎設施，目前不採用。重新辨識已完成或明確失敗的模型工作屬另一個新請求，不冒充原請求重試。

## 驗收與步驟

- [x] 先寫會失敗的案例：不點按鈕也會從 queued 更新到 succeeded、前景切換、重複 resume、401 停止、未送出草稿與已完成資料不重送。
- [x] 驗證斷線後 key/body 不變，重新開啟 App 後能續傳；明確 422、人工停止不自動重送。
- [x] 實作單一前景同步控制器、生命週期接線與等待原因提示。
- [x] Compose 檢查小螢幕／大字體的原因與備用操作，保留現有視覺風格。
- [x] 執行 testDebugUnitTest、lintDebug、assembleDebug，保存隔離合成測試與 APK 證據；工程結果與正式部署／手機實測分開回報。

Ruling：本次是既有同步行為的修正，直接沿用現有工作目錄並建立 feat/recognition-auto-progress；其餘未提交工作不動。

工程結果：Android 0.7.3/code 17，568 項測試、lintDebug 與 assembleDebug 通過；後端 487 項測試通過。獨立審查四項 Important 均以六個 RED→GREEN 案例修正。Git、正式部署與手機安裝依本版交付證據核對；免費資格恢復仍為獨立營運條件。

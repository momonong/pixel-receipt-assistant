# PixelReceipt 手機使用說明

0.7.0 起提供生活分類、餐別、商家與縣市分析，以及入帳後補填分析標籤。0.7.2 的應用程式名稱為 `PixelReceipt`，保留原大小寫與 App 資料；是否已發布供 App 更新，以當次交付紀錄為準。

## 生活分類、三餐、商家與縣市（0.7.0 起）

開底部「分析」，先看個人支出與生活分類。點「分析面向」可切換「餐別」、「店家」或「縣市」；「篩選」可組合日期、生活分類、餐別、品牌、縣市與地區。查舊帳時先選全部期間，避免本月篩選排除舊日期。食衣住行育樂以品項分類，早餐／午餐／晚餐按餐別統計；自己用及送人計入個人支出，代買另外列出。

舊帳目沒有分類時，金額仍保留在「未分類」；缺餐別或縣市不會憑空猜測。展開「資料待補」可看缺漏；點生活分類中的「未分類」可查看對應帳目。

補填方式：從「帳本」或分析下方「對應帳目」開啟帳目 → 點「分析標籤」→ 展開品項填生活分類／餐別，在店家欄填品牌、分店、縣市與地區 → 儲存。補填只更新分析標籤，不改原入帳金額、用途或照片；返回分析後更新相同條件，即可查看新分組。作廢帳目只供查閱。

完整定義與限制見 [生活支出分析](LIVING_SPENDING_ANALYSIS.md)。

## 圓環、折線與比較長條（0.7.2）

想知道吃飯花在哪些店，可在分類圓環點「食」，或按「餐飲都花在哪？」。餐飲畫面直接顯示店家占比及已知店家中累計花最多的一家；下方店家長條列出金額、占目前餐飲的比例、帳目筆數及每筆平均。點店家即可查看相關餐飲品項與原帳目；清除店家可回目前範圍的全部店家，返回分類占比則移除食類條件，其餘篩選保留。

比例以目前日期及篩選內的餐飲個人支出為分母。例如選午餐與臺南市，就比較這個範圍內各店的占比。混合購物收據只取食類品項的個人負擔，代買另列。店家依收據原名稱分組；品牌／分店另有分析面向。缺店名仍列在「店家待補」，不把未知店名當同一家真實商店。帳目筆數不代表實際到店次數，累計最多也不代表單價較貴。

圓環圖回答「錢花在哪裡」。圖例列金額與比例，點分類即可查看相關帳目。最多五個區塊，小分類會明示為「其餘 N 類」並可展開；未分類獨立保留。若含負的待分配調整，改用正負長條，避免比例圖誤導。零支出不畫假比例。

折線圖回答「支出怎麼變化」。各點依實際日期區間擺放，不做平滑預測、不補出不存在的消費；點圖，或按「前一筆／下一筆」查看精確日期和金額，再按「查看這個日期的帳目」。只有一個區間就畫一個點。缺日期的帳目及金額明示在圖下，保留於符合條件的總額，不硬放到今天。

「比較支出」預設比較餐別，可直接點「店家」或「縣市」。金額由大到小，以相同刻度長條比較；非餐飲另列並可點回帳目，餐別待補不隱藏。其餘分析面向保留在選單，超過五項可展開全部。圖表篩選沿用同一份日期與其他條件；切換範圍請用上方「篩選」。

一般手機直向排列。寬度至少 760dp 且字級不超過 130% 時，圓環與折線並排；較窄折疊畫面或放大字級維持單欄。原生繪圖、文字圖例與可點按的日期控制皆在 App 內，無須跳轉網頁。預覽使用明確標示的合成帳目，正式圖表讀取原中央分析 API。

## 收據管理與篩選（0.6.0）

首頁底部「收據」預設「一般收據」：正常的新收件、等待同步、中央處理中、待核對、已完成及參考成果仍可見。已刪除、已作廢、待補照片、辨識未完成、來源未就緒及等待過久的項目預設隱藏，資料與照片保留。

點「一般收據 ▾」開啟篩選，可選全部、需要處理或實際存在的單一狀態，按「顯示 N 筆收據」套用；重設返回一般。清單上方會顯示目前／全部筆數，需要處理可直接點數量。每種語意狀態有固定獨立顏色及文字。返回明細或旋轉後保留範圍。

中央開始處理超過 24 小時會顯示「等待較久」，結束輪詢仍未知則為「結果待查詢」；這只是顯示分類，不判為失敗或重新送出。中央時間缺失時不拿本機拍照日期推算。刪除、作廢與補名結果待確認仍留在一般清單，避免誤以為已成功。

## 互動支出分析（0.6.0）

點底部「分析」，預設本月截至今天，也可選上月、今年、全部或自訂日曆。主數字為整個期間已入帳且有效的個人支出，不只合計手機已載入的帳目；自己用及送人計入，代買另列。「金額怎麼算」顯示用途、實付及明列折扣；折扣已反映於帳目，不再次扣除，也不推測市場省下的金額。

前期比較旁會列出實際比較日期；本月與今年使用前期相同進度，月底依前期可用日數對齊。不用沒有基準的百分比暗示趨勢。全部和自訂沒有自動比較期。

點趨勢圖或「前一筆／下一筆」，往下看對應日期帳目；點店家則看該店家帳目。上方仍顯示完整本期支出，下方明確標示目前篩選；點「顯示本期全部帳目」清除。點帳目開 App 內明細，返回保留期間、選擇及捲動。店家以原始名稱分組，不推測不同分店是同一家；清單可繼續展開。

缺日期的歷史帳目不算入有日期範圍，會提示排除筆數；切換全部可查看缺日期帳目與其個人支出。一般手機直向排列；600dp 以上且字級足夠時，圖表和店家並排；放大字級回單欄，所有內容仍可捲動。

分析只在登入後顯示。離線保留符合目前期間的上次摘要、更新時間與提示，不以零假裝讀取成功；切換範圍不沿用其他期間金額。入帳、作廢及補名後將分析標為過期，開啟或返回分析時更新；未知作廢結果會另外提醒。衍生快取存於獨立私有檔，不佔用或改寫收據索引。

## 在 App 更新

開啟右上「設定」→「App 更新」→「檢查更新」。有新版時可直接按「下載更新」，畫面會顯示大小與進度；下載後按「安裝更新」交給 Android 確認，全程不需開網站。第一次可能顯示「允許安裝更新」：允許 PixelReceipt 安裝應用程式，再返回 App 繼續。這是 Android 系統設定與安裝確認；取消後可再操作，不會被標成更新成功。

更新採相同套件與永久簽章覆蓋，不卸載或清除收據、帳本、草稿與登入資料。舊版第一次仍需先安裝含此入口的 0.5.5，之後即可從 App 更新。是否已提供下載、部署及手機安裝，見當次交付證據。

0.7.2 起，安裝完成後會自動清除已安裝的 APK 更新包；重新開啟或回到 App 時也會補查。取消安裝或還沒安裝的新包會保留，原本的收據、照片、草稿、帳本與登入資料不受影響。下載途中不會清掉正在寫入的新包；暫時無法清理會稍後重試。先前從瀏覽器下載到「下載」資料夾的 APK 不由 App 管理。

更新僅在按鈕操作後查詢或下載，沿用中央帳本登入。未登入、連線失敗、更新檔改版或下載逾時會在同區提示，可重新檢查；下載中也可取消。離開後返回可繼續查看進度；程序中斷會停止該次工作，下次檢查會重新驗證完整檔，不安裝未完成檔。重新登入會停止舊更新工作，過期回應不清掉新登入。伺服器提供的版本較舊時不降版。

## 日常使用

1. 在相簿選取同一筆交易的 1–20 張收據、價標或促銷照片，分享到 PixelReceipt，也可從收件匣選照片。不同交易分批分享。分享文字會帶入整批說明。
2. 補上「牙膏幫朋友買」等整批或逐圖說明，確認照片角色與順序。點送出才上傳原圖與說明；送出後保留原批次、來源及請求內容。
3. 中央會繼續辨識，不必一直開著手機。返回 App 或按更新進度，查詢的都是原工作，不會另外建立辨識。
4. 辨識完成後點「前往帳本核對」。第一眼是店家、日期、實付、品項與用途；點「修改」才展開該項欄位。可改品名、數量、行金額、票面單價，也可新增／移除品項或折扣。
5. 品項辨識後會再對照整批與逐圖說明，帶入可對應的自己用、送人或代買建議，票面實付與個人支出分列。已保存用途保留，可明確選「依補充敘述套用用途」或「保留目前用途，已核對敘述」。部分數量、衝突或無法對應的敘述會提示核對，不會當作分類完成。編輯後自動保存，原圖與說明可在 App 查看。
6. 核對完後，按固定底部的「確認入帳」。這次操作會確認目前顯示的品項、金額、用途及收據完整。自動保存的內容是草稿。
7. 中央正式確認後，詳情、收件匣與帳本都顯示「已完成」。點開帳目可看品項、用途與個人支出／代買金額；作廢紀錄明確標示「已作廢」，保留原入帳內容供查閱。

0.6.0 首頁提供收據、帳本、分析、說明；其他頁面右上方也能開啟說明，返回後保留原內容與捲動位置。核對與帳本不使用外部瀏覽器或 WebView。

## 日期與待補品名

新草稿沒有辨識到日期時，先填裝置今天的日期，並提示來源；原始辨識值保留。點「消費日期」開日曆，也可按「今天」或「昨天」。已有日期和本機未保存編輯不會每天換成今天。從舊版已保存的空日期可直接按今天補上。

品名可以留空，不需要輸入假名稱。金額與用途確認後仍可入帳，顯示為「待補品名」；總覽會列待補數量，各筆帳目也有標示。進入帳目後點「補品名」或「修改品名」，只更新顯示名稱，原入帳金額、用途與原圖保留。斷線先查同一次補名結果；結果未確認前不能作廢，已作廢帳目不可改名。

## 送出前可能重複提醒

首次送出新收件前，App 會比對這台裝置中目前標為「收據」的整組相同原圖。命中時顯示「可能已分享過」，列出舊收件的時間、狀態與說明／頁序等差異，由你選擇查看哪一筆；不會自動合併或挑選。

- 「取消，返回新收件」或系統返回都不送出，新照片、整批與逐圖說明、角色、參考圖及順序保留。
- 查看舊收件只開原內容；原結果尚不確定時不會因開啟而另送辨識。之後明確繼續同步會接續原請求。已完成可查看帳目，已刪除／已作廢只保留歷史。
- 若確定是另一筆交易，選「仍另建一筆並送出」。同圖可以合法屬於不同交易。提示期間內容或候選改變，會要求重新確認。

比對只涵蓋本機資料，不代表中央或其他裝置沒有重複。重新拍攝、裁切、壓縮、更改檔案 bytes、增減頁面或更改圖片角色可能漏判。沒有提示時仍請核對交易分組；已送出的原請求重試不重新提醒，也不更換請求內容。

本功能隨 0.5.2／versionCode 9 整合；工程／合成 UI 驗證與發布、正式部署、手機更新分開核對。

## 刪除收據與作廢帳目

收件匣、收件詳情及帳本的「更多操作」會依目前狀態顯示對應動作。確認視窗列出店家與金額，取消不更動資料；完成後留在原分頁。

- **尚未入帳**：選「刪除收據」再確認。從收件匣移除，不影響帳本支出。這是耐久的邏輯刪除，原圖、原始紀錄與備份保留，介面沒有復原按鈕。
- **已完成**：選「作廢帳目」，原因預設「未註明」，可選重複入帳或資料有誤。作廢後不計入有效支出，原入帳內容及原因仍保留。收件匣會顯示已作廢；帳本勾選「查看已作廢」可查看歷史。
- **結果未知**：原目標 ID、原因、revision、key 與 body 會先保存。旋轉、重啟、斷線或連點不建立另一個未知操作。點「查詢刪除結果」或「查詢作廢結果」，先讀原 ID；仍需重試時沿同一份請求送出。
- **中央版本衝突**：不偷偷採用新 revision 刪除較新內容。已知被中央拒絕的操作保留紀錄；檢查最新狀態後，才能再次明確確認新的操作。未知操作則繼續保留原請求。

照片匯入／核對、草稿保存或入帳結果尚未確認時，先完成核對或查詢原結果。已鎖定但中央 ID 尚不明的收件，需要先沿原收件更新進度；刪除流程不會為了取得 ID 而新送一筆辨識。刪除待確認時不能繼續編輯或入帳。

帳本小卡顯示中央全部有效帳目的個人支出、實付及筆數，不加總手機已載入分頁。歷史列表的載入筆數包含已作廢紀錄，與有效筆數分開標示。操作後更新或失效收件投影、帳本列表、明細及中央統計；刷新失敗時明確顯示「尚未同步」與上次紀錄，請更新帳本。

## 用途與金額

- **自己用**：列為自己的消費。
- **送人**：贈送仍計入個人支出。
- **代買**：獨立列出代墊金額。
- **分攤**：可依購買數量分配，或同時指定各用途的數量與金額。每個用途都需填寫，沒有分配請明確填 0。數量與金額不一致時會在相關品項指出。

票面行金額就是該行合計，不再乘以數量。已含行金額的折扣只作對照，不會再扣一次；另外列出的折扣或加收，可設定整張收據或指定品項，再依金額比例或指定金額分配。

所有合計、差額及分攤來自中央確定性整數計算。App 接受既有契約的整數 TWD 元，不接受小數、負數或超出範圍的輸入；AI 只提供候選，不決定最後帳本值。差額或未知欄位在相關位置提示；容許範圍內的 1 元差額也須明確對照後接受。

## 尚未完整、斷線與衝突

品項缺漏可直接在原生核對頁補登。缺照片時，先勾選「目前缺照片或品項」保留草稿，再把完整照片另分享一批；原草稿保留，勿將新舊兩批重複確認入帳。已送出的原批次不能追加原圖。

不完整或尚未合法的輸入也會留在本機，例如數量只輸入 `1.`；不會把它改成 1 或 0。無法保存時，畫面保留目前編輯並阻擋送出，須先重試保存。請勿清除 App 資料。

自動保存回應不確定時，下次先讀正式草稿的 revision 及內容，再決定採認已保存結果或重試同一份內容。其他裝置變更時不覆蓋目前編輯；先比較中央與手機版本，再明確選擇保留內容。採用中央版本時，未採用的手機原稿另存保留。

確認入帳前會先保存固定的 review／confirm 內容及同一個 idempotency key。斷線、旋轉、重啟與連點不另產生入帳請求。按「查詢入帳結果」查正式草稿與帳目；只有中央正式確認才標示完成。尚未發出確認的版本衝突可以回到比對；已送出且結果未知的確認保留同一筆請求。

離線僅顯示上次已確認的中央狀態與同步提示。前景刷新有節流及數量上限；選中的歷史收件可個別更新，帳本支援分頁。這些讀取不會重跑辨識，也不覆寫未保存編輯。

## 登入與原圖

設定使用既有帳本密碼登入原生 reviewer session；密碼只用於當次登入，點登入後清空輸入欄，不寫入檔案。舊 ingest 登入仍能收件，首次原生核對須在設定重新登入一次。token 仍使用 Android Keystore AES-GCM 加密，登出只撤銷目前登入並保留草稿與原圖。

原圖 bytes 不改寫；單張上限 20 MiB、每批 100 MiB／20 張、本機圖片庫 1 GiB。分享原圖在 App 內縮放。歷史或其他裝置的帳目可能沒有本機原圖，此版本明確標示「此裝置未保存原圖」；帳目及核對內容仍可原生查看，未加入二進位下載／PDF 預覽管線。

## 工程契約與驗證

- 延用 `noBackupFilesDir/mobile-intake/`、AtomicFile、process／OS file lock、16 MiB 索引上限及 revision 保護；舊 App、歷史 APK 與原資料保留。
- 原生登入／登出為 `/v2/mobile/login`、`/v2/mobile/logout`；GET draft／ledger 沿用 v1，review PUT／confirm POST 沿用 v2。僅固定 HTTPS origin 與窄化 method/path allowlist，不跟隨 redirect，不記錄 token 或回應本文。
- 草稿 raw editor、partial-invalid 值、PUT 不確定狀態、最終固定 key/body、已 dispatch 階段均耐久保存。GET 不自動覆寫 dirty editor，autosave 不提交 `complete_by_user`。
- 帳本分頁 cursor 與任意 detail cache 分開；刷新保留已載入的分頁範圍，更新重疊帳目狀態，非目前頁面的舊明細失效並於開啟時重新讀取。前景收件查詢沿用節流與輪替上限，不一次查詢全部歷史收件。
- 刪除 POST 為 `/v1/intakes/{id}/delete` 或 `/v1/drafts/{id}/delete`，作廢為 `/v1/ledger/{id}/void`；三者都要求 reviewer 與固定 Idempotency-Key。中央統計讀取 `/v1/overview`；本機 tombstone 不能被舊投影復活。
- 沿用現有依賴，沒有新增供應商、背景服務、推論工作或付費呼叫。

離線驗證使用既有 JDK／Android SDK／Gradle cache，單 worker 執行：

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug --offline --no-daemon --max-workers=1 --no-parallel
```

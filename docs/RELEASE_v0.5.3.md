# PixelReceipt 0.5.3

Android `versionName=0.5.3`、`versionCode=10`，沿用 `com.momonong.pixelreceipt.mobile` 與既有永久 signer。可覆蓋更新並保留資料；不解除安裝或清除資料。中央服務版號、資料庫 schema、登入與辨識供應商不變。

## 修正行為

整批與逐張照片的說明原本已送入辨識。這次補上辨識後初次用途的銜接：例如獨立一句「貢丸湯幫別人買」，若能明確對應唯一單件品項，初次核對會預填代買。其他未指定用途的品項仍預設自己用。

票面實付、個人支出預估及代買分開顯示，金額由既有確定性整數規則計算。例如合成票面實付 300 元、代買 30 元，顯示個人支出 270 元；票面仍是 300 元。無法對帳時不顯示假定的支出金額。

模糊、衝突、重複品名或多數量描述不自動分配。既有人工核對、分攤與正式帳目優先，不用原備註重寫；代買品項的品名或數量改動後需重新選用途。最後仍需使用者確認入帳。

## 更新與驗證

後端與 Android App 需一起更新才能在原生核對中使用新建議；舊版 App 不會讀取可選的 `advance_suggestion` 欄位。手機可在既有 Dashboard 登入後下載認證 APK，直接覆蓋安裝，無須 USB。已有草稿與帳目不會因更新重分類。

0.5.3 發布候選已通過完整 Android gate：356 tests、嚴格 lint 與未簽 APK 建置；後端 332 tests、網頁 40 tests 與 Ruff。APK metadata 接受 10／0.5.3 並拒絕錯配；不將重跑相同案例加總。主機合成測試涵蓋真 MainActivity／ViewModel／Compose、實際後端與金額規則，以及模擬辨識來源；不代表新收據真實模型品質、手機已更新或本人帳務接受。

Git 合併推送、正式部署、永久簽章下載、手機安裝及新收據實測分別留證。私人收據、帳本、憑證、簽章私鑰與主機專用部署腳本留在本機，不加入 Git。操作見 [手機使用說明](MOBILE_APP.md)；前版見 [0.5.2](RELEASE_v0.5.2.md)。

# PixelReceipt 0.5.4 候選

Android `versionName=0.5.4`／`versionCode=11`，沿用 `com.momonong.pixelreceipt.mobile` 及原永久簽章。這份文件描述候選行為；Git 發布、正式部署、手機安裝及真人新收據接受各自留證。

## 本輪變更

- 品項辨識後，在原本同一次模型回覆核對整批與逐圖補充敘述，提供用途與原文引句。後端驗證品項位置、品名及敘述來源，金額繼續用確定性整數規則計算。舊工作保持原 payload／key 與解析方式，不額外呼叫模型。
- 自動儲存後仍保留敘述核對資訊。新草稿預填可對應的用途；已保存人工用途／分攤保留，使用者可明確套用提案或保留。目前用途與敘述衝突或仍無法對應時，需先核對，避免全算自己用卻顯示成功。已入帳金額不自動重分類。
- 新草稿缺日期時只預填一次裝置當日，原始日期仍為 null；既有輸入保留。日曆、今天／昨天快捷及中文日期取代手打格式。不是從照片推定出一個票面日期。
- 品名可空白而照常核對入帳，顯示「待補品名」。帳本總覽與各筆帳目標示待補數量；明細可補名／改名，只更新帶審計紀錄的顯示 metadata，財務 snapshot／用途／金額不變。固定 key/body、版本衝突、未知結果及與作廢互斥沿既有耐久流程處理。

## 驗證與限制

完整 Android 390 tests、`lintDebug`（No issues found）、`assembleDebug`、後端 388 tests、網頁 47 tests 與 Ruff 通過。獨立審查修正三項 Important 後複查為 Ready。使用真實後端／領域規則、原生 Repository／AtomicFile／Compose 及假辨識來源做回歸，包含模型漏判、相互衝突或引用其他品項用途、原文偽造、存檔復原、日期／日曆、空品名入帳、補名未知結果與作廢互斥。驗證結果在本輪私人交付證據記錄；尚未把合成測試寫成真實模型品質或手機已安裝證據。

本輪沒有新提供者、付費備援、資格延長、資料庫 migration 或共用主機變更。原收據、原始辨識結果、已有人工核對、私人憑證及歷史安裝包保留。原始日期與品名未被 placeholder 覆寫。操作見 [手機使用說明](MOBILE_APP.md)。

# PixelReceipt 0.6.0

Android versionName `0.6.0`／versionCode `13`，沿用 `com.momonong.pixelreceipt.mobile`。本文件描述此版本功能與工程驗證；Git 合併與推送、正式部署、APK 發布、手機安裝及使用者接受分別核對。

## 收據管理

每種狀態使用獨立淡底深字配色，文字同時表達狀態。預設一般收據保留正常新收件、待核對、已完成及參考成果；刪除、作廢、缺照片、失敗、來源未就緒與過久／未知工作預設隱藏。單一篩選入口可看全部、需要處理或某狀態，顯示筆數並可重設。

刪除或作廢結果待確認仍可見，不能以隱藏暗示成功。中央時間超過 24 小時只分類為等待較久，不重送、不更改工作；時間缺失不以照片日期判定。

## 支出分析

原生底部新增分析，支援本月、上月、今年、全部及自訂日曆。主數字為完整期間的有效已入帳個人支出；自己用與送人計入，代買另列。可查看金額構成、明列折扣與實際前期比較日期；不從個人支出重扣代買或內含折扣，不推測市場節省。

趨勢圖依真實日曆間距繪圖，點選或前後選取日期、點店家後可查看對應帳目。上方本期合計保留，下方標示選取範圍；開帳目明細再返回保留範圍與捲動。手機單欄，600dp 以上依字級並排，放大字級回單欄。店家原名不自動合併分店。

後端 `GET /v1/spending` 在單一 SQLite 讀取快照彙整完整有效帳目，摘要與比較同源，所有金額為既有確定性整數 TWD 元。帳目 API 在分頁前篩選店家與缺日期，支出摘要不受頁數影響。缺日期明示排除或另列，不虛構日期。獨立私有衍生快取失效不影響照片、說明或收據索引；離線標示上次資料，切換範圍不顯示前一範圍的金額。

## 相容與證據界線

不修改資料庫 schema、既有財務快照、照片 bytes、入帳／作廢請求、辨識提供者或 Broker。沿用既有登入及同源窄化唯讀 API；登入切換與查詢換範圍會使舊結果失效，不能以舊 401 清除新登入。

本版 Android 完整 453 tests、嚴格 lint（No issues found）及 assembleDebug 通過；後端完整 422 tests 與 Ruff／format 通過，既有 Web 3 個測試檔通過。獨立審查提出 3 Important／1 Minor，分別以負差額、旋轉、離線明細、待確認徽章的 4 項失敗重現後修正，針對 33 tests 轉綠，再通過上述完整 Android gate。原生 Compose 合成畫面與互動涵蓋 320dp／150% 字級、390dp、600dp、840dp 及短橫向，並驗證日曆、店家／日期、返回與保存。

工程測試、原生 Compose 合成資料畫面與不可變 APK 證據由當次交付保存。這些不代表正式服務部署、手機 OEM 安裝、TalkBack 或使用者帳務接受；本次開發未讀寫正式帳本、呼叫模型或安裝手機。
